# 部署手册

> 版本：v1.0 · 2026-11-12
> 目标环境：厂区内网 Linux 服务器 + Docker Compose
> 默认端口：前端 8080，后端 8000，PostgreSQL 仅容器内 5432

## 1. 前置条件

| 项 | 要求 |
| :--- | :--- |
| 操作系统 | Linux（推荐 Ubuntu 22.04/24.04、Rocky 9）或 Windows + Docker Desktop |
| Docker | 24.0+ |
| Docker Compose | v2.24+（支持 `env_file.required`） |
| 资源 | 2 vCPU / 2 GB 内存 / 10 GB 可用磁盘（180 天数据约 1 GB） |
| 网络 | 服务器可访问 LoRa 网关 TCP 端口；可访问 `open.feishu.cn`；内网用户可访问 8080 |
| 时间 | 服务器启用 NTP；容器 `TZ=Asia/Shanghai` |
| 数据 | 厂内存储，无需外网数据库 |

## 3. 首次部署

### 3.1 准备环境文件

```bash
cd motor_testing_system
cp .env.example .env
```

编辑 `.env`，至少确认：

```dotenv
TZ=Asia/Shanghai

POSTGRES_DB=motor_monitor
POSTGRES_USER=motor
POSTGRES_PASSWORD=请改成强密码

MP_COLLECTOR_MODE=modbus          # 生产必须为 modbus
MP_POLL_INTERVAL_MINUTES=15
MP_RUN_COLLECTOR=true
MP_POLL_ON_START=true

MP_AUTH_MODE=off                  # 接入 SSO 后改为 proxy
MP_DEFAULT_USER=设备科 · 观察员

MP_FEISHU_ENABLED=true
MP_FEISHU_WEBHOOK_URL=https://open.feishu.cn/open-apis/bot/v2/hook/xxxx
MP_FEISHU_WEBHOOK_SECRET=可选签名密钥

MP_LORA_FREQUENCY_MHZ=470
MP_LORA_BAUD_RATE=1200
```

> `.env` 含密码和 Webhook，必须保持在服务器本地，禁止提交 Git。

### 3.2 启动

```bash
docker compose up -d --build
docker compose ps
```

期望：

- `db` 为 healthy；
- `backend` 为 healthy；
- `web` 为 running；
- backend 日志出现 `Running database migrations...` 和 `采集调度器已启动，间隔 15 分钟`。

查看日志：

```bash
docker compose logs -f backend
docker compose logs -f web
```

### 3.3 验证

```bash
curl http://127.0.0.1:8000/api/v1/health
curl -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/
```

浏览器：

- 前端：`http://<服务器IP>:8080`
- API 文档：`http://<服务器IP>:8000/api/docs`

### 3.4 导入现场点表

1. 复制并修改：

```bash
cp config/points.example.yaml config/points.yaml
```

2. 按现场填写：
   - 网关 `host/port/framer`；
   - 电机铭牌 `rated_current_a`、阈值；
   - 传感器 `gateway/slave_id/register_address/register_count/scale`；
   - 未接线传感器保持 `enabled: false`。

3. 导入：

```bash
docker compose exec backend python -m app.cli import-points /app/config/points.yaml
```

4. 验证：

```bash
docker compose exec backend python -m app.cli collect-once
```

5. 页面“设备与链路”确认网关/采集点在线；总览出现读数。

> `import-points` 是幂等 upsert：重复执行不会重复创建；按 `code` 与 `motor_id+kind` 更新。

### 3.5 演示/验收数据（不要在生产库执行）

```bash
# .env 设置 MP_COLLECTOR_MODE=simulator
docker compose restart backend
docker compose exec backend python -m app.cli seed-demo --reset
```

演示数据会清空现有业务数据（保留配置），适用于验收演示环境。

## 4. 访问与网络

| 端口 | 暴露建议 |
| :--- | :--- |
| 8080 | 对厂区办公网开放；建议只开放给设备科/生产科网段 |
| 8000 | 仅运维调试使用；生产建议不对办公网开放，或在防火墙限制 |
| 5432 | 不映射到宿主机 |

如果前端与后端同机，Nginx 已把 `/api` 代理到 `backend:8000`，浏览器无需直接访问 8000。

### 4.1 SSO 接入

推荐拓扑：

```text
浏览器 -> SSO/oauth2-proxy -> Nginx(web) -> FastAPI
```

配置：

```dotenv
MP_AUTH_MODE=proxy
MP_AUTH_PROXY_HEADER=X-Auth-User
MP_AUTH_ROLE_HEADER=X-Auth-Role
```

要求：

- SSO 网关注入 `X-Auth-User`（用户名或工号），可选 `X-Auth-Role`；
- 该头只能由受信代理设置，禁止客户端直接伪造；
- 未登录访问 API 返回 401；
- 审计日志中的 `actor` 为用户头值。

示例（oauth2-proxy 已在前面完成登录，Nginx 仅透传）：

```nginx
proxy_set_header X-Auth-User $http_x_auth_user;
proxy_set_header X-Auth-Role $http_x_auth_role;
```

> 当前仓库只实现应用侧适配；具体 IdP 参数由信息部门提供。

## 5. 飞书配置

1. 在飞书群添加“自定义机器人”，复制 Webhook。
2. 设置 `.env`：

```dotenv
MP_FEISHU_ENABLED=true
MP_FEISHU_WEBHOOK_URL=https://open.feishu.cn/open-apis/bot/v2/hook/xxxx
MP_FEISHU_WEBHOOK_SECRET=如启用签名则填写
```

3. 重启 backend：

```bash
docker compose restart backend
```

4. 设置页 → 发送测试消息；或：

```bash
curl -X POST http://127.0.0.1:8000/api/v1/settings/feishu/test
```

5. 在设置页维护通知群名、责任人、级别开关、夜间静默（22:00–06:00，严重告警不受限）。

## 6. 升级

```bash
cd motor_testing_system
git pull                     # 或替换代码包
docker compose build
docker compose up -d
docker compose logs -f backend
```

- backend 入口自动执行 `alembic upgrade head`；
- 数据库卷 `pgdata` 保留；
- 升级前建议备份：

```bash
docker compose exec -T db pg_dump -U motor -d motor_monitor \
  | gzip > backup_$(date +%Y%m%d_%H%M).sql.gz
```

## 7. 备份与恢复

### 7.1 备份

```bash
mkdir -p backups
docker compose exec -T db pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
  | gzip > backups/motor_$(date +%Y%m%d).sql.gz
```

建议加入 crontab（每日 02:00，保留 14 天）：

```cron
0 2 * * * cd /opt/motor_testing_system && docker compose exec -T db pg_dump -U motor -d motor_monitor | gzip > backups/motor_$(date +\%Y\%m\%d).sql.gz && find backups -name "motor_*.sql.gz" -mtime +14 -delete
```

### 7.2 恢复

```bash
gunzip -c backups/motor_20261112.sql.gz \
  | docker compose exec -T db psql -U motor -d motor_monitor
docker compose restart backend
```

| :--- | :--- | :--- |

## 9. 故障排查

### 9.1 前端打开空白或 502

```bash
docker compose ps
docker compose logs web
docker compose logs backend
```

- `web` 未启动：查看构建日志；
- `/api` 502：确认 backend healthy、容器名 `backend` 可解析；
- 401：`MP_AUTH_MODE=proxy` 但未注入 `X-Auth-User`。

### 9.2 网关连接失败

- 在 backend 容器内测试：

```bash
docker compose exec backend python - <<'PY'
import socket
s = socket.create_connection(("10.112.66.231", 10123), timeout=3)
print("connected")
s.close()
PY
```

- 检查网关 IP/端口、RTU/TCP 模式、防火墙；
- 日志出现 `连接网关失败` 会触发“LoRa 网关离线”告警；
- `framer` 必须与网关透传方式一致：现场脚本使用 RTU over TCP → `rtu`。

### 9.3 Modbus 异常响应/数值不对

- 核对从站地址（温度 1、电流 3 为测试示例，现场以实际为准）；
- 核对寄存器地址与数量；
- 核对 `scale`：温度 0.1、电流 0.01（测试脚本注释，需现场比对）；
- 用 `collect-once` 查看 `readings.raw` 原始寄存器；
- 若数值正负颠倒，确认 int16 有符号处理。

### 9.4 告警不发送飞书

- 设置页确认“飞书已配置”；
- 检查 `MP_FEISHU_ENABLED=true`、Webhook URL；
- 检查夜间静默（22:00–06:00 只发严重）；
- 检查级别开关；
- 查看 `notification_logs` 的 `status/response_body`；
- 飞书机器人是否被移出群/Webhook 失效。

### 9.5 告警闭环后马上又出现

- 已内置 30 分钟抑制（`MP_ALARM_SUPPRESSION_MINUTES`）；
- 若超过 30 分钟仍出现，说明工况未恢复，属于预期；
- 可调整阈值或延长抑制窗口。

### 9.6 数据库迁移失败

```bash
docker compose logs backend | tail -50
docker compose exec backend alembic current
docker compose exec backend alembic history
```

- 确认 `MP_DATABASE_URL` 正确；
- 确认 `db` healthy；
- 恢复备份后重试；
- 不要手工删表，先备份。

## 10. 安全检查清单

- [ ] `.env` 未提交 Git，权限 600。
- [ ] `POSTGRES_PASSWORD` 已改，非默认 `change-me`。
- [ ] 8000 端口未对办公网开放（或仅运维网段）。
- [ ] 生产 `MP_AUTH_MODE=proxy`，SSO 已生效。
- [ ] 飞书 Webhook 仅环境变量保存。
- [ ] 备份任务已配置并验证恢复。
- [ ] 服务器 NTP 正常。
- [ ] 容器以非 root 运行（可选加固）。
- [ ] 日志保留/磁盘监控已配置。
- [ ] 现场点表已复核并版本化。

## 11. 验收部署步骤（建议）

1. 在部署机执行 `docker compose config` 校验；
2. `docker compose up -d --build`；
3. 三容器 healthy；
4. 导入真实点表；
5. `collect-once` 核对温度/电流；
6. 配置飞书并发送测试；
7. 配置 SSO 并验证 401/登录；
8. 触发一次真实阈值告警，确认 1 分钟内飞书送达与闭环；
9. 重启 backend，确认采集恢复且数据不丢；
10. 按 [验收功能文档](04-验收功能文档.md) 逐项签字。
